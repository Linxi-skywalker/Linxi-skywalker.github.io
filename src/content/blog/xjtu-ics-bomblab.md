关于 `p` 和 `x`，最重要的就是记得 `p` 命令用于打印表达式的值，而 `x` 命令则主要用于检查内存的内容。几个常用示例如下：

```bash
p $rax  # 打印寄存器 rax 的值
p $rsp  # 打印栈指针的值
p/x $rsp  # 打印栈指针的值，以十六进制显示
p/d $rsp  # 打印栈指针的值，以十进制显示

x/2x $rsp  # 以十六进制格式查看栈指针 %rsp 指向的内存位置 M[%rsp] 开始的两个单位。
x/2d $rsp # 以十进制格式查看栈指针 %rsp 指向的内存位置 M[%rsp] 开始的两个单位。
x/2c $rsp # 以字符格式查看栈指针 %rsp 指向的内存位置 M[%rsp] 开始的两个单位。
x/s $rsp # 把栈指针指向的内存位置 M[%rsp] 当作 C 风格字符串来查看。

x/b $rsp # 检查栈指针指向的内存位置 M[%rsp] 开始的 1 字节。
x/h $rsp # 检查栈指针指向的内存位置 M[%rsp] 开始的 2 字节（半字）。
x/w $rsp # 检查栈指针指向的内存位置 M[%rsp] 开始的 4 字节（字）。
x/g $rsp # 检查栈指针指向的内存位置 M[%rsp] 开始的 8 字节（双字）。

```

这些命令在 `/` 后面的后缀（如 `2x`、`2d`、`s`、`g`、`20c`）指定了查看内存的方式和数量。具体来说：

-   第一个数字（如 `2`、`20`）指定要查看的单位数量。
-   第二个字母（如 `x`、`d`、`s`、`g`、`c`）指定单位类型和显示格式，其中：

    -   `c` / `d` / `x` 分别代表以字符 / 十进制 / 十六进制格式显示内存内容。
    -   `s` 代表以字符串格式显示内存内容。
    -   `b` / `h` / `w` / `g` 分别代表以 1 / 2 / 4 / 8 字节为单位（`unit`）显示内存内容。

        当使用 `x/b`、`x/h`、`x/w`、`x/g` 时，`unit` 会保留对应改变，直到你再次使用这些命令。

这一题的逻辑是比较简单的：容易看到将`（%rip）+0x1c6e`的值传入第二个参数代表的寄存器`rsi`，然后调用`strings_not_equal`
判断你传入的字符串（作为第一个参数）和答案（也就是现在rsi寄存器存的值），一样返回0或者不一样返回1, 再执行`test   %eax,%eax`  判断返回值：等于 0 → 不跳转；不等于 0 → 跳转（爆炸），最后恢复栈帧

那么答案就藏在`rsi`寄存器中，
首先我们需要知道几个基本的点：
-  **静态地址** 反汇编中显示的短地址（如 `0x15cb`、`0x3248`），是程序文件内的相对位置，不随运行改变。
- **基地址** 程序被加载到内存时的起始地址（PIE 程序常见 `0x555555554000`），每次运行可能不同。 
- **运行时地址** 内存中真实有效的地址，CPU 与 GDB 实际使用的地址。（`0x5555555555cb`）

比如这段程序的基地址可以这样找到：`0x5555555555cb`-`0x15cb`=`0x555555554000`

这里我们先了解栈**金丝雀（Stack Canary）防栈溢出原理**：

*金丝雀是一个随机数，放置在栈中“局部变量缓冲区”与“函数返回地址”之间。
利用栈溢出必须从*  **低地址向高地址覆盖** *的特性，任何覆盖返回地址的攻击，都会先破坏金丝雀。 函数返回前检查金丝雀是否被篡改，从而发现并阻止攻击。

是这样的原理：
- **`%rbp` 是什么？全称 `Base Pointer`（栈基址指针），是** 栈的 “定位锚点”：
    
    - 函数用它来快速找到局部变量、函数参数的位置；
    - 每个函数执行时，都会**修改 `rbp`** 指向自己的栈空间。
- **为什么要 push 保存？** 是函数调用的标准开头：
    
    - 当前函数马上要**覆盖 `rbp` 的值**（改成自己的栈基址）；
    - 但 `rbp` 里还存着**上一个函数的栈锚点**，如果直接覆盖，上一个函数执行完就找不到自己的栈了，程序会崩溃；
    - 所以必须先 `push %rbp`，把旧值存到栈里，等函数执行完再恢复。
 - **`%rbx` 是什么？**  普通通用寄存器，用来存临时数据（比如计算中间值、循环变量）。
    
- **为什么要 push 保存？**x86-64 有严格的**寄存器调用规则**：
    
    - `rbx` 属于**被调用者必须保护的寄存器**；
    - 意思是：**当前函数如果要用 `rbx`，必须先保存它原来的值，函数退出前再还原**；
    - 否则上一个函数存在 `rbx` 里的数据会被覆盖，导致程序出错。 

数据是怎么存的呢？：`1609: 48 89 e6 mov %rsp,%rsi ; rsi = 栈顶地址 → 准备存放输入的6个数字` 这是将栈顶指针复制到%rsi，因为下一行需要调用`160c: e8 6b 07 00 00 call 1d7c <read_six_numbers> ; 调用函数 → 读取 6 个数字到栈上 ;`，这个函数需要一个参数：*这个参数告诉函数你要把读到的6个数字放在内存的哪个位置*，因此之后将从栈顶开始读你输入的6个数字

注意这里是用`0x4(%rsp)` ：从栈顶地址加上4个字节的地址找到第二个数字
事实上，栈顶存的6个数字相当于一个数组 `int num[6]`，而栈顶地址（rsp）也就指向了数组的起始地址
这里我们很容易知道前两个数字就是0,1

然后执行了

将rsp传递给rbx，这时，rbx就指向了数组的起始地址（也就是第一个数）
然后通过lea指令计算地址：`0x10(%rsp)`即4个int（4字节）的偏移，容易知道：
- rsp+0x00 -> num[0] **第一个数字0**
- rsp+0x04 -> num[1] **第二个数字1**
- .......
- rsp+0x10 -> num[4]  **第五个数字**，也就是说lea指令让rbp指向了数组中的第五个数字，作为循环结束的边界（至于为什么是第五个数，为什么是循环结束的边界，后面我们会知道）

```
162d: 48 83 c3 04 add $0x4,%rbx ; rbx += 4 → 指向下一个 int（4字节） 
1631: 48 39 eb cmp %rbp,%rbx ; 比较：是否到达循环终点（rbp） 
1634: 74 11 je 1647 ; 如果 rbx == rbp → 结束循环，通关 ; 
```

通过不断让`rbx`加上`$0x4`，其实就是不断访问数组的每个元素（也可以理解为指针不断向后移，指向下一个整数）
然后判断`rbx`和`rbp`是否相等，也就是是否到达循环结束的边界，如果循环结束就通关

那么循环是如何实现的，或者说循环执行的逻辑是怎样的，就是这道题的核心：

```
1636: 8b 43 04 mov 0x4(%rbx),%eax ; eax = 下一个数字 
1639: 03 03 add (%rbx),%eax ; eax = 当前数字 + 下一个数字 
163b: 39 43 08 cmp %eax,0x8(%rbx) ; 比较：再下一个数字 是否等于 前两个之和 
163e: 74 ed je 162d ; 如果相等 → 继续循环 ; 如果不相等 → 顺序执行爆炸 
1640: e8 df 06 00 00 call 1d24 <explode_bomb> ; 炸弹爆炸！ 
1645: eb e6 jmp 162d ; 跳回循环（不会执行到） ; 
```

容易看出循环的逻辑是比较简单的：先用eax存下一个数字，然后再把当前数字加上下一个数字，最后判断下下一个数字是否等于前两个数字之和，如果相等，则继续循环，不相等就爆炸。其实逻辑也就是**斐波那契数列**

**答案也就呼之欲出：0 1 1 2 3 5**

事实上，因为执行到`0xc(%rbx)`第四个数字停止，就可以通过0x8(%rbx)找到`第六个数字`，然后判断是否符合条件，而我们使用的add逻辑（+=）会在做完第四个数字检查后再加上4,变成0x10,因此这就是循环结束的边界

- `0xf3` 是十六进制 → 十进制 **243**
- `0x14(%rsp)` = **你输入的第二个整数**
**作用**：比较：你输入的第二个数字 是否等于 243

- 3 → 546（0x222）+ `g`

- 6 → 171（0xAB）+ `v`
- 7 → 941（0x3AD）+ `u`
